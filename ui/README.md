# ui

Artrios local web UI: a small Node server with a React front end, running on `localhost`, that shows workspaces and a task
board, runs skills in headless mode, and embeds a terminal. Work in progress (PRD AIOS-55 v3, build task AIOS-63).

Sign-in (PRD AIOS-61 v2.0 S1): one account, `administrator`, no roles. Set its password with `npm run password` (the installer asks), start with `npm start`, open the address it prints, sign in, and choose your own password at the first sign-in. Forgot it: run `npm run password` again. `data/users.json` holds the scrypt hash (never in git); sessions are an `HttpOnly SameSite=Strict` cookie kept in memory, so a restart signs you out; five wrong passwords in a row lock the account for 15 minutes (`loginMaxFailed`, `loginLockMinutes`, `sessionIdleMinutes` 720, `sessionMaxHours` 168 in `data/config.json`). The server binds `127.0.0.1`; `"host": "<LAN address>"` opens it to other devices, still behind the sign-in and the Host/Origin check (`"allowedHosts"` adds names; `"0.0.0.0"` needs them). Sign-ins, password changes and the terminal go to `data/audit.jsonl`.

Agent Terminals (menu A) is off by default: hidden and its API refused. Settings > Terminal switches it on after a warning (written to `data/config.json` as `"terminal": true`); turning it off closes open terminals. Screens (sidebar, one letter each): Cognition (C), Kanban Board (K), Agent Terminals (A), Overview (O: Activity, Changelog, Context and MCP), Insights (N), Ideation (I), Brain (B: 3D knowledge graph of the sources in `data/brain.config.json`, the screen shows an example when the file is missing), Worktrees (W), Routines (H: Schedules, Agents, Today). New Task is T. Light and dark themes, 3D Brain look.

Start and the scheduler (PRD AIOS-61 v2.1 S2, S2a): `npm start` runs `bin/start.js`, which starts two processes, the UI (`server/index.js`, also `npm run ui`) and the scheduler (`server/scheduler-main.js`, also `npm run scheduler`, `--log FILE` for a run without a console). Ctrl+C stops both; the UI stopping on its own leaves the scheduler and its jobs running. A scheduler that finds another one alive for the same data folder exits quietly, so a logon task and `npm start` can coexist (on Windows: a Task Scheduler logon task running `conhost.exe --headless node server/scheduler-main.js --log data/scheduler/scheduler.log`, no time limit; on Linux: a systemd service). It opens no port: every `schedulerTickMs` (default 10000), and at once when the UI drops a run request, it reads the schedules, runs one whose cron time fell within the last 2 minutes, and files one "Jadwal terlewat" (`missed_run`) item in Decision Required for every time that fell while it was off or asleep, key `jadwal/<schedule>/<YYYY-MM-DDTHH:MM>`, never twice; "jalankan sekarang" runs it, "lewati" closes it. It writes `data/scheduler/heartbeat.json` and `state.json`.

Routines (S3, S7, menu H) has three tabs, Schedules, Agents and Today: a schedule says when and where, an agent profile says who.
- Schedule, `schedules/<id>.md` (`schedulesDir`, default `data/schedules`): `name`, `enabled`, `schedule` (5-field cron, local time; the form builds it from Every day / Weekdays / Every week / Every month / Every N hours / Every N minutes / custom), `location` (`artrios` = the Artrios home folder from `cognitionHome`, the default, or a workspace key), then either `command` (one program line run without a shell from that folder, `timeout` seconds, `exitWarn` exit codes that mean "succeeded with findings", e.g. a health check) or `agent` (a profile id; none = the default read-only agent), `skill` (`/name args`) and the prompt as the body. `output` is a note for the list.
- Agent profile, `agents/<id>.md` (`agentsDir`, default `data/agents`): `name`, `description`, `engine` + `model` (picked with the same model picker as Settings; empty = the main model), `allowedTools`, `approval`, `budget` (`{ maxUsd, maxMinutes }`), default `location`, then the role (standing instructions, put before every schedule prompt). A profile used by a schedule cannot be deleted.
- `approval`: `report-only` (only read tools `Read, Grep, Glob, LS, WebFetch, WebSearch, TodoWrite` are passed), `ask-before-write` (read tools only; a write attempt stops the run as `waiting_approval` and an "Izin agen" item asks; `setuju` resumes the same session with the full `allowedTools`, `revisi` runs the read phase again with the note, `tolak` closes it `rejected`, no answer in 7 days closes it `expired`), `ask-before-run`, `auto`. Over `budget.maxUsd` or `budget.maxMinutes` the run stops as failed and files a "Budget terlewati" item (`jalankan ulang` / `tutup`).
- Runs log in `<location>/.artrios/jobs/` like button jobs, masked for secrets. Status words in the list: Succeeded, Succeeded with findings, Failed, Running, Waiting for approval, Not run yet; hover a pill for the detail. Other machines' routines (`artrios/routines.yaml` with another `host`, e.g. the VPS) are listed read-only from their logs. Broken files are listed with the reason; the rest keeps running.

Git and worktrees (PRD AIOS-61 v2.1 S11, `server/git-service.js`): Worktrees (menu W) lists every worktree of the workspace as a card: branch, linked task cards, files changed, lines added and removed and commits ahead of the base branch (the branch of the main folder, or `git.baseBranch`), uncommitted changes, `base > branch`, and the buttons Check for Conflicts (`git merge-tree`, changes nothing), Merge to main (plain merge, fast-forward when possible, only into a clean main folder and only without conflict; a failed merge is aborted), Create PR (push + `gh pr create`), Copy Path, Open in Cognition (the worktree opens as a chat folder under its workspace, key `<KEY>~<hash>`), Open Terminal, VS Code, folder, and Delete (refused while the worktree has uncommitted changes or unmerged commits until you confirm again; an unmerged branch is always kept, a merged one is deleted with the worktree). New worktree makes one for a new or existing branch at `<repo>/.artrios/worktrees/<branch>` (`.artrios/` is added to `.git/info/exclude` when missing), never in the workspace list. Start (and Create and start) on a card has "Run in worktree": the card gets branch `artrios/<key>` and its worktree (reused on the next run), stored as `branch` and `worktree` in the card file; the job and its AI review run there and the main folder is not touched; the card's Human Review shows the same summary and buttons, Merge moves the card to Done and Create PR to PR created. A terminal tab can start in a worktree and carries its branch as a label. A Repository bar shows branch, upstream, ahead and behind, with Fetch and Pull (`--ff-only`). Settings > Git: commit identity (`git config --global`), the credential helper, GitHub (Connect GitHub runs `gh auth login --web`: the screen shows the one-time code and a link to github.com/login/device and waits; after the sign-in `gh auth setup-git` lets git push with it; Disconnect runs `gh auth logout`; the Worktrees screen has the same Connect button), Test connection (`git ls-remote`), and the push switch: `"git": { "allowPush": false }` by default, so Create PR is hidden until it is turned on (written to `data/config.json` and the audit log). Agents never push: headless jobs and API-provider tools run with a git setting that rewrites every push URL to a scheme git cannot use, so any `git push` fails and the job log and activity feed record "push refused". The kit stores no git token or password. Other keys: `git.remote` (default `origin`), `git.gh` (the gh command as an argv list). Git older than 2.38 uses the old `git merge-tree` form for the conflict check.

UI conventions (every new screen and form follows these; they are the house style, not a per-task request): page = `PageHeader` (title, one-line intro, actions right); content = `SettingsSection` cards (`components/settings-layout.jsx`: icon circle, title, intro, action) with `SettingRow` rows (label and description left, controls right); dropdowns = `SelectField`, never a native `<select>`; text = `Field` + `FIELD_FULL` inputs and `components/ui/textarea`; model choice = `ModelPicker` (`components/model-picker.jsx`), never a free text box; forms open in a `Dialog` with `DialogHeader`, `DialogBody`, and `DialogFooter` (a `<form>` wrapping them must be `flex min-h-0 flex-1 flex-col`, or the body cannot scroll and the footer is cut off on a short window) (ghost Cancel, primary Save with a spinner while busy), `role="alert"` errors; status = a small rounded pill in plain words with the detail on hover, never a raw code (FAIL, BLOCKED); ids are suggested from the name; UI choices (menu, tabs, filters, workspace, Cognition session and new-chat model/effort/mode) survive a reload through `client/src/lib/persist.js` (per browser, guarded, never for shared state); the brand is `components/brand-mark.jsx` (inline, follows the theme) and `client/public/favicon.svg` (boxed tab icon; `node bin/make-icons.mjs <dir holding playwright-core>` renders `favicon-32.png`, `apple-touch-icon.png`, `icon-512.png`; the icons load before sign-in, nothing else does); all UI text lives in `client/src/texts.js` (`T.views.<screen>`); check light and dark, and a narrow window, before calling a screen done.

The UI calls each registered folder a workspace. Code, API routes (`/api/projects`), JSON keys, and data files (`data/projects.json`, `.artrios/project.json`) keep the name `project`.

## CLI

```
node bin/artrios-task.js add --project AIOS --client "Client A" --title "Example" --priority high
node bin/artrios-task.js list --project AIOS
node bin/artrios-task.js move AIOS-1 in_progress
node bin/artrios-task.js note AIOS-1 "short dated note"
node bin/artrios-task.js prio AIOS-1 urgent AIOS-2
node bin/artrios-task.js label AIOS-1 waiting -quick
node bin/artrios-task.js list --all --label waiting
```

Tasks root: `--root`, else `ARTRIOS_TASKS_ROOT`, else `./.artrios/tasks`. If `.artrios/project.json` exists, its `nextIndex`
is honored and advanced so task numbers are never reused.
